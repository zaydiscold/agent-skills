# Scope and discovery

Use this when the intended skill boundary or selection behavior is uncertain. Infer answers from the current conversation and relevant evidence first. A user who has asked for a broad pointer has already answered the breadth question.

## Questions worth asking, selectively

| Decision | Natural question | Why it matters |
| --- | --- | --- |
| Outcome | What should become easier or more reliable when this skill is used? | Identifies the missing capability or preference rather than adding generic advice. |
| Breadth | This exact operation, a family of similar jobs, or a broad domain guide? | Determines procedural detail and routing. |
| Discovery | What would you naturally ask when you want this help? What similar request should use something else? | Supplies positive phrases and near misses. Draft these yourself from existing examples when possible. |
| Outputs | What should the agent leave you with, and what should it explain before acting? | Captures deliverables and meaningful review boundaries. |
| Flexibility | Which choices are fixed, and where should the agent exercise judgment? | Keeps preferences from becoming unnecessary universal rules. |
| Context | Is this for your environment, a team, or portable use elsewhere? Which records own changing facts? | Separates local knowledge from reusable method. |
| Improvement | What went wrong before, what worked, and how would you judge the next result? | Establishes a useful comparison and protects successes. |

Ask one to three high-value questions at a time, not the whole table. Recommend a reasonable default. If the answer is already clear, proceed and state only consequential assumptions. Do not require users to invent keywords, evaluation jargon or an architecture. A small requested correction usually needs no interview.

## Shape the skill to its purpose

- Specific procedure: explicit inputs, fragile ordering, verifiable outputs and bounded retries where needed.
- Reusable method: decision criteria, defaults with alternatives, examples that vary and appropriate constraints.
- Domain entry point: orientation, source ownership, capability discovery, selective links, learning responsibilities and handoff conditions. Keep detailed execution in focused skills or maintained sources.

A skill can combine these at different levels. Avoid both a narrow recipe masquerading as a general guide and a catchall that claims unrelated work. Link to known capabilities; include a discovery fallback instead of freezing the ecosystem to a list of tools.

## Discovery review

Describe capability plus recognizable task contexts in ordinary language. Test paraphrases and implicit needs as well as exact names. Include adjacent tasks sharing the same nouns but requiring a different capability. Check overlap with existing skills. Tune precision and coverage together; avoid keyword stuffing or importing runtime-specific under-triggering remedies without evidence in this runtime.

When automatic selection is testable, expose only the normal catalog metadata during that test. Loading the skill body or explicitly invoking it answers a different question. If automatic selection cannot be measured, label the result a description review and keep live selection unverified.
